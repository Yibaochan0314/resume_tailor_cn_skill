# 经历档案（Experience Archive）· 模板与使用说明

> 本文件既是**使用说明**，也是**可直接复制的空模板**。
> 建议把它复制成 `经历档案-<你的名字>.md` 放在简历项目目录里，之后所有岗位定制都从这份档案全量选材。

---

## 一、它是什么，为什么必须有

经历档案是你**全部职业素材的唯一权威数据源**，比简历本身更全：

- 简历只有 2 页，装不下所有项目、所有数据、所有细节；
- 档案不限篇幅，记录原始事实（做了什么、什么背景、什么数字、什么难点）；
- 定制简历时按 JD 匹配度从档案里**挑最合适的案例**呈现，不同岗位挑不同组合。

**核心规则：档案只增不改。** 新经历/新数据就追加一节，历史内容一律保留。这样随着投递岗位变多，你的选材池只会越来越大。

---

## 二、档案更新机制

### 2.1 两类归档来源

| 来源 | 说明 |
|---|---|
| **① 主动同步** | 你随时发来新工作经历、新项目、新数据、新荣誉、新技能 → 当场追加到档案，标注来源与日期 |
| **② 定制过程中的问答** | 定制某岗位时，若因 JD 匹配需要向你提问（尤其匹配度 <50% 时的 5 轮深挖）→ 你的回答**当场结构化归档**，因为这些答案往往是后续岗位的稀缺素材 |

### 2.2 归档格式（问答类）

每条问答归档按这五要素记录：

```
岗位：<该次定制的岗位名>
问题：<当时问的问题>
回答要点：<你的回答>
可引用数据：<回答中出现的、可写进简历的数字>
日期：<YYYY-MM-DD>
```

### 2.3 数据溯源闸门（强制）

**任何数字进入档案时，就要建立「数字 → 出处」映射。**

- 出处可以是：原始报表、周报、后台截图、上级确认、你自己的记录。
- 简历引用时必须能回到档案里的这一行；**查不到出处的数字一律不许写进简历**，也不要用"约""左右"稀释蒙混。
- 常见致命错误：把 A 项目的数据写到 B 项目下；凭印象编造"看起来合理"的数字；把公司级整体成果算作某个具体项目的产出。

### 2.4 维护动作

1. 新增内容后同步 Git 存档（见 `git-workflow.md`）。
2. 每季度回看一次，把当时没记数据的经历补上数字。
3. 档案里可保留"待确认"标记，但**带待确认标记的数字不得进简历**。

## 四、填写要点

1. **先堆事实，后做包装**：档案里写"我做了什么、结果怎样"，不用管文采。包装是定制简历时的事。
2. **数字宁缺毋滥**：想不起准确数字就标注"待确认"，绝不用估计数充当真实数据。
3. **把"我"和"团队"分清**：档案里明确写你在其中的角色，避免简历里把团队成果写成个人成果——面试一问就穿。
4. **难点要留档**：当时觉得麻烦的事，恰恰是简历里"项目复杂度"的素材来源，别嫌琐碎。
5. **沉淀物别漏**：SOP、模型、模板、方法论——这类"可复用产出"在跨行业投递时是最强的可迁移证据。
